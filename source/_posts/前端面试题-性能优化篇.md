## 四、性能指标

### Core Web Vitals

| 指标 | 名称 | 优秀阈值 | 良好阈值 | 需改进 |
|------|------|---------|---------|--------|
| LCP | 最大内容绘制 | < 2.5s | 2.5s - 4s | > 4s |
| FID | 首次输入延迟 | < 100ms | 100ms - 300ms | > 300ms |
| CLS | 累计布局偏移 | < 0.1 | 0.1 - 0.25 | > 0.25 |

### 其他常见性能指标

| 指标 | 名称 | 说明 |
|------|------|------|
| FP | 首次绘制 | 第一个像素渲染到屏幕 |
| FCP | 首次内容绘制 | 第一块内容渲染完成 |
| LCP | 最大内容绘制 | 视口内最大元素渲染完成 |
| TTI | 可交互时间 | 页面完全可交互的时间 |
| TBT | 总阻塞时间 | FCP 到 TTI 之间的总阻塞时间 |
| SI | 速度指数 | 页面可视区域填充速度 |

## 五、网络层优化

### 1. DNS 优化

- **DNS 预解析**：`<link rel="dns-prefetch" href="//example.com">`
- **减少域名数量**：减少 DNS 查询次数
- **使用 CDN**：就近访问，加速 DNS 解析

### 2. HTTP 请求优化

- **减少 HTTP 请求**：合并文件、雪碧图
- **使用 HTTP/2**：多路复用、头部压缩、服务器推送
- **使用预连接**：`<link rel="preconnect" href="...">`
- **预加载关键资源**：`<link rel="preload" href="...">`
- **预获取**：`<link rel="prefetch" href="...">`

### 3. 资源压缩

- **Gzip / Brotli 压缩**：服务器开启压缩
- **HTML 压缩**：移除空格、注释
- **CSS 压缩**：移除空格、合并选择器
- **JS 压缩混淆**：UglifyJS、Terser
- **图片压缩**：WebP、AVIF 格式，压缩工具

## 六、缓存策略

### 1. 浏览器缓存

**强缓存：**
- `Cache-Control: max-age=31536000`（HTTP/1.1）
- `Expires`（HTTP/1.0，绝对时间）
- 状态码：200 (from memory/disk cache)

**协商缓存：**
- `Last-Modified / If-Modified-Since`（基于时间）
- `ETag / If-None-Match`（基于内容哈希，更精确）
- 命中：304 Not Modified
- 未命中：200 + 新内容

### 2. 缓存位置优先级

1. **Service Worker**：自定义缓存策略，离线可用
2. **Memory Cache**：内存缓存，快，容量小，关闭标签页失效
3. **Disk Cache**：磁盘缓存，稍慢，容量大，持久化
4. **Push Cache**：HTTP/2 推送缓存，会话级

### 3. 缓存最佳实践

- **HTML**：协商缓存，保证及时更新
- **CSS/JS/图片**：强缓存 + 文件名哈希，更新时改变文件名
- **不常变的资源**：设置较长的 max-age
- **CDN 缓存**：配合浏览器缓存使用

## 七、渲染性能优化

### 1. 减少重排重绘

**触发重排的操作：**
- 添加/删除 DOM 元素
- 改变元素位置、大小、内容
- 改变浏览器窗口大小
- 获取某些属性（offsetWidth、clientWidth 等）

**优化方法：**
- 使用 transform 做动画（不触发重排，直接走合成层）
- 使用 opacity 做动画（走合成层）
- 使用 class 批量修改样式
- 离线操作 DOM（DocumentFragment）
- 用 will-change 或 translateZ 提升为合成层
- 避免频繁读取布局属性

### 2. JS 执行优化

- **防抖（debounce）**：事件停止触发后 n 秒执行
- **节流（throttle）**：每隔 n 秒执行一次
- **长列表虚拟滚动**：只渲染可视区域
- **Web Worker**：将计算密集型任务放到 Worker
- **requestIdleCallback**：空闲时执行低优先级任务
- **避免内存泄漏**：及时清理定时器、事件监听

### 3. 图片优化

- **懒加载**：`loading="lazy"`、IntersectionObserver
- **响应式图片**：`srcset` + `sizes`、`<picture>` 标签
- **使用合适的格式**：WebP、AVIF 优先
- **图片预加载**：关键图片提前加载
- **雪碧图**：小图标合并
- **字体图标 / SVG**：代替图片图标

## 八、代码层面优化

### 1. JavaScript 优化

- **减少作用域查找**：避免多层嵌套，缓存全局变量
- **减少 DOM 操作**：批量操作，使用 DocumentFragment
- **事件委托**：利用事件冒泡，减少事件绑定
- **避免 with / eval**：性能差，安全问题
- **合理使用缓存**：Memoization、缓存计算结果
- **Tree Shaking**：移除未使用的代码
- **代码分割**：按需加载，减少首屏代码量

### 2. CSS 优化

- **避免过深的选择器嵌套**：建议不超过 3 层
- **优先使用高性能属性**：transform、opacity
- **避免使用 @import**：用 link 代替
- **提取关键 CSS**：内联到 head 中
- **避免通配符选择器**：* 选择器性能差
- **减少重排重绘**：用 transform 代替 top/left

## 九、构建优化

### 1. Webpack / Vite 优化

- **按需引入**：babel-plugin-import、unplugin-auto-import
- **Tree Shaking**：移除死代码
- **代码分割（Code Splitting）**：按路由/模块分割
- **预构建（Pre-build）**：Vite 的依赖预构建
- **依赖优化（externals）**：将大依赖外部化，用 CDN 引入
- **压缩优化**：JS 压缩、CSS 压缩、图片压缩
- **缓存优化**：利用 webpack 缓存，提升二次构建速度

### 2. 首屏优化

- **路由懒加载**：按需加载路由组件
- **骨架屏**：提升感知性能
- **关键 CSS 内联**：首屏样式内联到 HTML
- **预渲染 / SSR**：服务端渲染，提升首屏速度和 SEO
- **DNS 预解析**：`<link rel="dns-prefetch">`
- **资源预加载**：preload 关键资源
- **减少首屏资源体积**：压缩、Tree Shaking

## 十、移动端性能优化

### 1. 移动端特有问题

- **点击延迟 300ms**：使用 fastclick 或 touch 事件
- **移动端性能较差**：减少动画、减少 DOM 操作
- **流量敏感**：图片压缩、按需加载
- **内存限制**：避免内存泄漏、及时释放资源

### 2. 移动端优化手段

- **使用 CSS3 动画**：GPU 加速
- **避免大规模重排重绘**：用 transform、opacity
- **合理使用 touch 事件**：代替 click 事件
- **图片自适应**：响应式图片、不同尺寸图片
- **离线存储**：Service Worker、LocalStorage
- **减少重绘**：用 canvas 代替大量 DOM

## 十一、性能优化方法论

### 1. 性能优化步骤

1. **性能测量**：用工具测出当前性能指标
2. **分析瓶颈**：找出性能问题的根源
3. **制定优化方案**：针对性地制定优化策略
4. **实施优化**：按照方案进行优化
5. **验证效果**：再次测量，验证优化效果
6. **持续监控**：建立性能监控机制

### 2. 优化原则

- **先测量后优化**：不要凭感觉优化
- **二八原则**：20% 的问题带来 80% 的性能提升
- **感知性能**：用户感知比数据更重要
- **权衡取舍**：在性能、开发成本、可维护性之间平衡
- **渐进式优化**：先解决主要瓶颈，再优化细节
