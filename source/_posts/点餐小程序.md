## 项目概述

本项目是一款基于 uni-app + Vue3 开发的无后端点餐小程序，采用纯前端技术栈实现，模拟了真实外卖点餐的完整流程。项目已成功打包为 H5 版本并部署在个人博客上，可随时随地在线访问体验。

作为一个完整的点餐系统，它涵盖了商品浏览、购物车管理、订单提交、支付模拟等核心功能，界面设计简洁美观，交互流畅自然，完美复刻了主流外卖平台的用户体验。

> 该项目非常适合作为前端学习练手项目，帮助开发者掌握 uni-app 跨端开发、购物车逻辑、状态管理等核心技术点。

## 技术栈详解

### 前端框架

- **uni-app**：基于 Vue.js 的跨端框架，一套代码可发布到 iOS、Android、H5、微信小程序等多个平台
- **Vue3 Composition API**：使用最新的 Vue3 组合式 API，代码组织更灵活，逻辑复用更方便
- **uni-ui**：官方 UI 组件库，提供丰富的基础组件，开发效率高

### 状态管理

- **Vue 响应式系统**：利用 Vue 的响应式特性管理购物车、订单等状态
- **Provide/Inject**：跨组件状态传递
- **LocalStorage**：本地持久化存储，保存购物车数据、订单记录等

### 部署方案

- **Hexo 博客**：静态网站生成器，作为项目部署载体
- **GitHub Pages**：免费的静态网站托管服务
- **Hash 路由**：使用哈希路由模式，避免部署后页面 404 问题

首页采用左侧分类导航 + 右侧商品列表的经典外卖点餐布局，用户可以快速浏览和选择商品。

**功能特点：**
- 左侧分类导航栏，支持上下滚动

- 点击分类快速切换商品列表
- 商品支持加减购物车操作
- 购物车数量角标实时更新

点击商品可查看详细信息，了解商品的具体情况。

**功能特点：**

- 规格选择（如辣度、份量等）

- 实时计算商品总价

### 4. 订单确认与提交

确认选购商品后，进入订单确认页面，填写收货地址等信息。

**功能特点：**

## 核心功能实现详解

### 购物车逻辑实现

购物车是点餐系统的核心，以下是关键实现思路：

```javascript
// 购物车数据结构
const cart = {
  goods: [
    {
      id: 1,
      name: '商品名称',
      price: 29.9,
      count: 2,
      image: '/static/goods/1.jpg'
    }
  ],
  totalPrice: 59.8,
  totalCount: 2
}

// 添加商品
function addGoods(goods) {
  const exist = cart.goods.find(item => item.id === goods.id)
  if (exist) {
    exist.count++
  } else {
    cart.goods.push({ ...goods, count: 1 })
  }
  updateTotal()
  saveCart()
}

// 减少商品
function decreaseGoods(goodsId) {
  const index = cart.goods.findIndex(item => item.id === goodsId)
  if (index > -1) {
    if (cart.goods[index].count > 1) {
      cart.goods[index].count--
    } else {
      cart.goods.splice(index, 1)
    }
    updateTotal()
    saveCart()
  }
}
```

## 部署到 Hexo 博客详细教程

### 第一步：配置 uni-app 项目

打开项目根目录下的 `manifest.json` 文件，切换到**源码视图**，在文件末尾添加 H5 配置节点：

```json
"h5" : {
    "publicPath": "/demos/sellH5-project/",
    "router": {
        "mode": "hash"
    },
    "title": "点餐小程序",
    "optimization": {
        "treeShaking": {
            "enable": true
        }
    }
}
```

**配置说明：**
- `publicPath`：静态资源路径前缀，必须与部署目录一致
- `router.mode`：路由模式，必须使用 `hash` 才能在静态托管下正常工作
- `title`：网页标题
- `optimization`：开启 treeShaking 优化打包体积

### 第二步：打包 H5 静态文件

在 HBuilderX 中执行以下操作：

1. 点击顶部菜单：**发行** → **网站 - H5 手机版**
2. 在弹出的配置框中确认网站标题和域名
3. 点击**发行**按钮开始打包

打包完成后，生成的静态文件位于：

```plaintext
/unpackage/dist/build/h5/
```

### 第三步：复制到 Hexo 博客目录

进入 Hexo 博客项目，在 `source/demos/` 目录下新建文件夹 `sellH5-project`（文件夹名需与 publicPath 配置一致）。

将打包好的 `h5` 文件夹内的**所有文件**复制到 `source/demos/sellH5-project/` 目录下。

### 第四步：执行 Hexo 部署命令

打开终端，进入 Hexo 博客根目录，执行一键部署命令：

```bash
hexo clean && hexo g && hexo d
```

### 第五步：在线访问验证

部署完成后，等待几分钟即可通过以下地址访问项目：

```plaintext
https://xumin8888.github.io/demos/sellH5-project/
```

## 常见问题排查指南

### 问题一：页面空白、样式丢失

**可能原因：**
- 未配置 `publicPath` 或配置错误
- 静态资源路径不正确

**解决方案：**
1. 检查 `manifest.json` 中的 `publicPath` 配置
2. 确保路径格式为 `/demos/sellH5-project/`（前后都有斜杠）
3. 重新打包并覆盖部署文件

### 问题二：图片等资源 404 报错

**可能原因：**
- publicPath 配置与实际部署路径不一致
- 资源文件未正确复制

**解决方案：**
1. 确认 publicPath 与部署目录完全匹配
2. 检查 `static` 目录下的资源文件是否完整
3. 不要使用 `./` 相对路径，必须使用绝对路径前缀

### 问题三：页面跳转后刷新 404

**可能原因：**
- 使用了 history 路由模式
- 静态托管服务器不支持 history 模式

**解决方案：**
1. 将路由模式改为 `hash` 模式
2. 重新打包部署
3. 确认 URL 中包含 `#` 符号

### 问题四：购物车数据丢失

**可能原因：**
- 清除了浏览器缓存
- 使用了无痕模式浏览

**解决方案：**
1. 购物车数据存储在 LocalStorage 中，清除缓存会丢失
2. 如需持久保存，可接入后端接口存储
3. 正常模式下关闭浏览器再打开数据仍在
