## 前言

前端性能优化是前端工程师必备的核心技能之一。一个性能优秀的网站，不仅能提升用户体验，还能提高转化率、降低服务器成本。本文将从多个维度全面讲解前端性能优化的各种手段。

## 一、性能指标解读

### 1.1 核心 Web 指标（Core Web Vitals）

- **LCP（Largest Contentful Paint）**：最大内容绘制，应小于 2.5 秒
- **FID（First Input Delay）**：首次输入延迟，应小于 100 毫秒
- **CLS（Cumulative Layout Shift）**：累计布局偏移，应小于 0.1

### 1.2 其他重要指标

- **FP（First Paint）**：首次绘制
- **FCP（First Contentful Paint）**：首次内容绘制
- **TTI（Time to Interactive）**：可交互时间
- **TTFB（Time to First Byte）**：首字节时间

## 二、加载性能优化

### 2.1 资源压缩

```javascript
// webpack 配置
module.exports = {
  optimization: {
    minimize: true,
    minimizer: [
      new CssMinimizerPlugin(), // CSS 压缩
      new TerserPlugin({ // JS 压缩
        terserOptions: {
          compress: {
            drop_console: true // 移除 console
          }
        }
      })
    ]
  }
}
```

### 2.2 图片优化

- 选择合适的格式：WebP > JPEG > PNG
- 使用响应式图片：`srcset` + `sizes`
- 图片懒加载

```html
<picture>
  <source srcset="image.webp" type="image/webp">
  <img src="image.jpg" alt="图片" loading="lazy">
</picture>
```

### 2.3 代码分割

```javascript
// 路由懒加载

// 按条件加载
button.addEventListener('click', async () => {

```

### 2.4 Gzip / Brotli 压缩


### 2.5 CDN 加速

- 静态资源放到 CDN 上
- 不同地区用户从最近的节点获取资源
- 减轻源站压力

## 三、缓存策略

### 3.1 浏览器缓存

| 缓存方式 | 说明 |
| --- | --- |
| 强缓存 | 不发送请求，直接使用本地缓存 |
| 协商缓存 | 发送请求验证资源是否有更新 |

**强缓存（HTTP 1.0）：**
```http
Expires: Wed, 21 Oct 2026 07:28:00 GMT
```

**强缓存（HTTP 1.1）：**
```http
Cache-Control: max-age=3600
```

**协商缓存：**
```http
ETag: "abc123"
Last-Modified: Wed, 21 Oct 2025 07:28:00 GMT
```

### 3.2 Service Worker 缓存

```javascript
// 注册 Service Worker
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js')
}

// sw.js
self.addEventListener('install', event => {
  event.waitUntil(
    caches.open('v1').then(cache => {
      return cache.addAll(['/', '/index.html', '/style.css'])
    })
  )
})

self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request).then(response => {
      return response || fetch(event.request)
    })
  )
})
```

## 四、渲染性能优化

### 4.1 减少重排重绘

**会触发重排的操作：**
- 添加/删除 DOM 元素
- 元素位置、尺寸变化
- 内容变化（文字数量、图片大小）
- 页面初次渲染
- 浏览器窗口尺寸变化

**优化技巧：**
```javascript
// 1. 使用 class 批量修改样式，而不是逐个修改 style
element.classList.add('active')

// 2. 使用 DocumentFragment
const fragment = document.createDocumentFragment()
for (let i = 0; i < 100; i++) {
  const li = document.createElement('li')
  fragment.appendChild(li)
}
list.appendChild(fragment)

// 3. 先 display:none，操作完再显示
element.style.display = 'none'
// ... 多次 DOM 操作
element.style.display = 'block'
```

### 4.3 使用 CSS 动画代替 JS 动画

CSS 动画由合成线程处理，不会阻塞主线程：

```css
/* ✅ 推荐：使用 transform 和 opacity */
.element {
  transition: transform 0.3s ease;
}
.element:hover {
  transform: translateX(100px);
}

/* ❌ 避免：使用 top/left 会触发重排 */
.element {
  position: relative;
  transition: left 0.3s ease;
}
.element:hover {
  left: 100px;
}
```

## 五、JavaScript 性能优化

### 5.1 防抖和节流

```javascript
// 防抖：多次触发只执行最后一次
function debounce(fn, delay) {
  let timer = null
  return function(...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}

// 节流：规定时间内只执行一次
function throttle(fn, interval) {
  let last = 0
  return function(...args) {
    const now = Date.now()
    if (now - last >= interval) {
      last = now
      fn.apply(this, args)
    }
  }
}
```

### 5.2 Web Worker

把耗时计算放到 Worker 线程，不阻塞主线程：

```javascript
// 主线程
const worker = new Worker('worker.js')
worker.postMessage({ data: bigData })
worker.onmessage = e => {
  console.log('结果:', e.data)
}

// worker.js
self.onmessage = e => {
  const result = heavyCalculation(e.data)
  self.postMessage(result)
}
```

### 5.3 内存优化

```javascript
// 避免意外的全局变量
function foo() {
  bar = 123 // 意外的全局变量，不会被回收
}

// 及时清除定时器和事件监听
const timer = setInterval(() => {}, 1000)
// 组件卸载时
clearInterval(timer)

// WeakMap/WeakSet 用于缓存，不影响 GC
const cache = new WeakMap()
function process(obj) {
  if (cache.has(obj)) return cache.get(obj)
  const result = heavyCalc(obj)
  cache.set(obj, result)
  return result
}
```

## 七、性能监控

### 7.1 使用 Performance API

```javascript
// 测量代码执行时间
console.time('expensive')
expensiveFunction()
console.timeEnd('expensive')

// 使用 Performance API
performance.mark('start')
doSomething()
performance.mark('end')
performance.measure('myMeasure', 'start', 'end')
const measure = performance.getEntriesByName('myMeasure')[0]
console.log(measure.duration)
```

### 7.2 上报性能数据

```javascript
// 页面加载完成后上报
window.addEventListener('load', () => {
  const timing = performance.timing
  const data = {
    dns: timing.domainLookupEnd - timing.domainLookupStart,
    tcp: timing.connectEnd - timing.connectStart,
    ttfb: timing.responseStart - timing.requestStart,
    domReady: timing.domContentLoadedEventEnd - timing.navigationStart,
    load: timing.loadEventEnd - timing.navigationStart
  }
  // 上报到监控系统
  reportPerformance(data)

```

## 八、总结

前端性能优化是一个系统性工程，需要从多个维度入手：

1. **加载优化**：资源压缩、代码分割、缓存策略、CDN
2. **渲染优化**：减少重排重绘、虚拟列表、CSS 动画
3. **JS 优化**：防抖节流、Web Worker、内存管理
4. **首屏优化**：骨架屏、预加载、SSR
5. **性能监控**：及时发现和定位问题

性能优化没有银弹，需要根据实际情况选择合适的方案，不断迭代优化。
