## 前言

在开发完 uni-app 项目后，如何将其部署到线上供他人访问是一个常见问题。对于没有后端依赖的纯前端项目，我们可以利用 Hexo 博客的静态资源目录来快速部署，既方便又免费。

本文将详细介绍如何将无后端的 uni-app 项目打包为 H5 版本，并部署到 Hexo 博客上，实现在线访问和项目展示。无论你是想展示个人作品集，还是分享 demo 项目，这篇教程都能帮到你。

> 本教程适用于所有纯前端项目，包括 uni-app、Vue、React 等，只需稍作调整即可通用。

## 核心前提

在开始之前，请确保你已经满足以下条件：

- ✅ Hexo 博客已搭建完成，可正常部署（`hexo g` / `hexo d` 命令可用）
- ✅ uni-app 项目本地可正常运行
- ✅ 项目无后端接口依赖（纯前端 Mock 数据或本地存储）
- ✅ 了解基本的命令行操作

## 为什么选择 Hexo 部署

### 优势

1. **免费托管**：GitHub Pages、Vercel 等平台免费提供静态网站托管
2. **零运维**：无需购买服务器，无需配置环境
3. **一键部署**：Hexo 提供便捷的部署命令
4. **统一管理**：项目和博客文章统一管理，方便维护
5. **访问速度快**：CDN 加速，全球访问都很快

### 适用场景

- 个人项目作品集展示
- 前端 Demo 效果预览
- 学习项目分享
- 产品原型演示

## 单个项目完整部署步骤

### 第一步：配置 uni-app 项目（必做）

这一步是关键，直接决定了部署后页面能否正常显示。

打开项目根目录下的 `manifest.json` 文件，切换到**源码视图**，在文件末尾添加 `h5` 配置节点：

```json
"h5": {
    "publicPath": "./",
    "router": {
        "mode": "hash"
    },
    "title": "项目名称",
    "optimization": {
        "treeShaking": {
            "enable": true
        }
    }
}
```

**配置项详细说明：**

| 配置项 | 作用 | 注意事项 |
|--------|------|----------|
| `publicPath` | 静态资源路径前缀 | 必须配置，否则样式和图片会丢失 |
| `router.mode` | 路由模式 | 必须使用 `hash`，否则刷新会 404 |
| `title` | 网页标题 | 可选，显示在浏览器标签页 |
| `optimization.treeShaking` | 摇树优化 | 可选，减小打包体积 |

> ⚠️ **重要提醒**：`publicPath` 有两种写法：
> - 使用 `./`：相对路径，部署到任何目录都能工作（推荐）
> - 使用 `/demos/项目名/`：绝对路径，必须与实际部署目录一致

### 第二步：打包 H5 静态文件

在 HBuilderX 中执行以下操作：

1. 点击顶部菜单栏：**发行** → **网站 - H5 手机版**
2. 在弹出的配置窗口中确认网站标题和域名
3. 点击**发行**按钮开始打包

等待打包完成，生成的静态文件位于：

```plaintext
项目根目录/unpackage/dist/build/h5/
```

打包完成后你会看到类似这样的目录结构：

```
h5/
├── index.html
├── static/
│   ├── js/
│   ├── css/
│   └── img/
└── ...
```

### 第三步：Hexo 博客新建目录

进入 Hexo 博客项目，在 `source/demos/` 目录下新建一个英文文件夹。

> 文件夹命名建议：使用英文、小写、无空格、无特殊符号，例如：`study-system`、`sell-app`、`my-demo` 等

**为什么放在 demos 目录？**
- Hexo 的 source 目录下的文件都会被复制到生成的静态网站中
- 统一放在 demos 目录下便于管理多个项目
- URL 结构清晰：`https://你的域名/demos/项目名/`

如果 `source/demos/` 目录不存在，请手动创建。

### 第四步：复制打包文件

将打包好的 `h5` 文件夹内的**所有文件和文件夹**，复制到刚才新建的 Hexo 博客目录下。

> ⚠️ **注意**：是复制 h5 文件夹**里面**的内容，不是复制 h5 文件夹本身！

最终目录结构应该是这样的：

```
blog/
└── source/
    └── demos/
        └── your-project/    ← 你的项目文件夹
            ├── index.html
            ├── static/
            └── ...
```

### 第五步：执行 Hexo 部署命令

打开终端，进入 Hexo 博客根目录，依次执行以下命令：

```bash
# 1. 清理缓存和旧的生成文件
hexo clean

# 2. 生成静态文件
hexo generate
# 或简写
hexo g

# 3. 部署到远程服务器
hexo deploy
# 或简写
hexo d
```

也可以使用组合命令一键完成：

```bash
hexo clean && hexo g && hexo d
```

等待部署完成，通常需要几十秒到几分钟不等。

### 第六步：在线访问验证

部署完成后，等待几分钟让 CDN 缓存更新，然后通过以下格式的地址访问：

```plaintext
https://你的用户名.github.io/demos/你的项目名/
```

例如：

```plaintext
https://xumin8888.github.io/demos/study-system/
```

访问成功后，建议：
- 测试所有页面跳转是否正常
- 检查图片、样式是否正确加载
- 在手机端也测试一下

## 多个项目批量部署流程

如果你有多个项目需要部署，流程基本相同，只需重复操作即可。

### 通用部署步骤

1. **配置**：每个 uni-app 项目都要配置 `manifest.json` 的 h5 节点
2. **打包**：分别打包每个项目的 H5 版本
3. **建目录**：在 `source/demos/` 下为每个项目建一个文件夹
4. **复制文件**：将每个项目的打包文件复制到对应目录
5. **一键部署**：执行一次部署命令即可

```bash
hexo clean && hexo g && hexo d
```

6. **验证访问**：逐个项目验证是否正常访问

### 多个项目的目录结构

```
blog/
└── source/
    └── demos/
        ├── project1/
        │   ├── index.html
        │   └── static/
        ├── project2/
        │   ├── index.html
        │   └── static/
        └── project3/
            ├── index.html
            └── static/
```

## 其他前端框架项目部署

### Vue 项目部署

修改 `vite.config.js` 或 `vue.config.js`：

```javascript
// vite.config.js
export default {
  base: './'  // 或 '/demos/vue-project/'
}
```

然后执行打包：

```bash
npm run build
```

将 `dist` 目录内容复制到 Hexo 的 `source/demos/vue-project/` 目录。

### React 项目部署

修改 `vite.config.js`：

```javascript
// vite.config.js
export default {
  base: './'
}
```

或在 `package.json` 中添加：

```json
{
  "homepage": "./"
}
```

然后执行打包，将 `build` 或 `dist` 目录内容复制到 Hexo 对应目录。

## 必看避坑指南

### 1. 不能直接双击 index.html 打开

很多同学打包后习惯双击 `index.html` 查看效果，结果发现页面空白。

**原因**：浏览器安全策略限制，本地文件协议（file://）下很多功能无法正常工作。

**正确做法**：部署到服务器后访问，或使用本地服务器预览。

```bash
# 使用 VS Code 的 Live Server 插件
# 或使用 http-server
npx http-server ./h5
```

### 2. 目录命名规范

- ✅ 使用英文小写
- ✅ 使用连字符或下划线分隔单词
- ❌ 不要使用中文
- ❌ 不要有空格
- ❌ 不要有特殊符号（!@#$%^&* 等）

**好的命名：**
- `study-system`
- `sell-app`
- `my-demo`

**不好的命名：**
- `学习系统`（中文）
- `my project`（有空格）
- `项目1#`（特殊符号）

### 3. publicPath 配置是关键

99% 的页面样式丢失、图片不显示问题，都是 `publicPath` 配置错误导致的。

- 如果不确定部署路径，使用 `./` 相对路径最稳妥
- 如果使用绝对路径，必须与实际部署目录完全一致
- 修改配置后一定要重新打包

### 4. 路由模式必须是 hash

静态托管环境下，`history` 模式的路由刷新会 404。

**uni-app 配置：**
```json
"router": {
    "mode": "hash"
}
```

**Vue Router 配置：**
```javascript
import { createRouter, createWebHashHistory } from 'vue-router'

const router = createRouter({
  history: createWebHashHistory(),
  routes: [...]
})
```

### 5. 只复制内容，不复制文件夹

常见错误：把整个 `h5` 文件夹复制过去，导致访问路径变成 `/demos/项目名/h5/`。

**正确做法**：打开 `h5` 文件夹，全选里面的所有文件，复制过去。

### 6. 部署后不生效？

- 可能是 CDN 缓存，等待几分钟或强制刷新（Ctrl + F5）
- 检查是否执行了 `hexo d` 命令
- 检查 GitHub 仓库是否有更新
- 确认部署目录是否正确

## 常见问题快速排查

### 问题一：页面完全空白

**可能原因：**
1. 未配置 `h5` 节点
2. 路由模式不是 hash
3. publicPath 配置错误

**排查步骤：**
1. 按 F12 打开开发者工具
2. 查看 Console 面板是否有报错
3. 查看 Network 面板是否有资源加载失败
4. 检查 manifest.json 配置是否正确

### 问题二：样式错乱、图标不显示

**可能原因：**
1. publicPath 配置错误
2. 静态资源路径不对

**解决方案：**
1. 确认 publicPath 配置为 `./` 或正确的绝对路径
2. 重新打包并部署
3. 检查图片、字体等资源是否都复制过去了

### 问题三：点击跳转后刷新 404

**可能原因：**
- 使用了 history 路由模式

**解决方案：**
1. 将路由模式改为 hash
2. 重新打包部署
3. 确认 URL 中包含 `#` 符号

### 问题四：访问不到项目，显示 404

**可能原因：**
1. 目录放错位置
2. 未执行部署命令
3. URL 输入错误

**排查步骤：**
1. 确认文件放在了 `source/demos/项目名/` 目录
2. 确认执行了 `hexo clean && hexo g && hexo d`
3. 检查 URL 是否正确，注意大小写
4. 等待 CDN 缓存更新

### 问题五：手机端显示不正常

**可能原因：**
1. viewport 配置问题
2. 样式适配问题

**解决方案：**
1. 检查 `index.html` 中的 viewport meta 标签
2. 使用响应式布局
3. uni-app 项目使用 rpx 单位

## 进阶技巧

### 1. 自定义域名

如果你有自己的域名，可以配置自定义域名访问：

1. 在 Hexo 根目录的 `source` 下创建 `CNAME` 文件
2. 内容填写你的域名，如 `www.example.com`
3. 在域名服务商处配置 DNS 解析

### 2. 压缩优化

部署前可以对静态资源进行压缩，提升访问速度：

- 使用 `terser` 压缩 JS
- 使用 `cssnano` 压缩 CSS
- 使用 `tinypng` 压缩图片
- 开启 gzip 压缩

### 3. 版本管理

建议将项目源代码和打包后的文件都纳入 Git 管理：
- 源代码放独立仓库
- 打包文件放 Hexo 的 source/demos 目录

### 4. 项目列表页

可以创建一个项目列表页面，统一展示所有 demo 项目：

```markdown
---
title: 项目作品集
---

## 我的项目

- [线上学习系统](/demos/study-system/)
- [点餐小程序](/demos/sellH5-project/)
- [数据可视化大屏](/demos/data-dashboard/)
```

## 总结

通过本教程，你应该已经掌握了如何将 uni-app 项目部署到 Hexo 博客的完整流程。回顾一下关键步骤：

1. 配置 `manifest.json` 的 h5 节点（publicPath + hash 路由）
2. 打包 H5 版本
3. 复制文件到 Hexo 的 `source/demos/项目名/` 目录
4. 执行 `hexo clean && hexo g && hexo d`
5. 在线访问验证

整个流程虽然简单，但有很多细节需要注意。只要按照教程一步步操作，就能成功部署。

> 💡 **小提示**：如果遇到问题，优先检查 publicPath 和路由模式这两个配置，90% 的问题都出在这里。
