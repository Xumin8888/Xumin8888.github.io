《前端fetch请求大模型API踩坑汇总》

## 前言

上一篇我实战完成了 Hexo 博客接入 AI 对话机器人，全程使用原生 `fetch` 调用大模型接口。

看似简单的前端请求，我在部署、调试过程中**踩了一堆只有前端才会遇到的坑**：跨域、报错不显示、请求格式错误、密钥泄露、Hexo 编译报错、加载状态异常等等。

很多教程只教「怎么写成功请求」，不教「为什么失败」。

这篇文章我汇总**我个人真实实操踩坑**，全部是前端直接调用大模型 API 的高频问题，给同样想做 AI 前端落地的同学避坑。

## 一、坑点1：直接前端调用大模型，浏览器 CORS 跨域报错

### 问题现象

代码本地看着没问题，控制台直接爆红：

> No ‘Access-Control-Allow-Origin’ header is present on the requested resource

请求发出去了，但是浏览器直接拦截，拿不到任何返回数据。

### 真实原因

所有大模型官方 API（豆包、GPT、通义千问）**都不允许前端直接跨域调用**。

浏览器同源策略限制：前端域名和 API 域名不一致，服务端没有配置允许跨域，浏览器直接拦截复杂请求。

### 为什么本地有时能行、线上必炸？

本地 `hexo s` 本地服务有宽松策略，偶尔能通；**部署到线上 GitHub Pages / 静态服务器 100% 跨域**。

### 解决方案（前端专属）

1. 开发阶段：浏览器跨域插件临时调试
2. 生产阶段：**必须接口代理中转**

不能把真实大模型 API 直接暴露在前端，必须通过代理/云函数中转请求，彻底解决跨域。

## 二、坑点2：前端明文写 API\_KEY，密钥直接泄露

### 问题现象

很多新手（包括我刚开始）直接把密钥写在 JS 里：

|  |  |
| --- | --- |
| ``` 1 ``` | ``` const API_KEY = "sk-xxxx你的密钥"; ``` |

### 致命问题

前端所有代码都是公开的！

任何人打开浏览器开发者工具 → Sources，**1 秒复制你的密钥**，盗刷你的 API 额度、滥用接口。

### 正确结论

**前端绝对不能存放任何密钥**。

这也是为什么必须用后端/云函数代理的第二个核心原因：隐藏密钥。

## 三、坑点3：fetch 默认不带错误捕获，报错空白不提示

### 问题现象

接口 404、401、500 报错，前端页面毫无反应，用户以为卡住了。

### 核心原因（90%前端不知道）

**fetch 只要收到响应就不会走 catch**。

哪怕是 401、403、404、500 错误码，依然进入 `then`，不会触发异常捕获。

### 我踩坑场景

密钥填错、模型 ID 不对、额度耗尽，页面一直 loading，没有任何文字提示。

### 正确写法（我最终落地版）

必须手动判断 `res.ok`

|  |  |
| --- | --- |
| ``` 1 2 3 4 ``` | ``` const res = await fetch(url, options) if (!res.ok) {   throw new Error("接口请求异常") } ``` |

## 四、坑点4：Hexo YAML 缩进问题导致全站编译失败

### 真实报错

> YAMLException: bad indentation of a mapping entry

### 踩坑经历

我在 inject 里粘贴 CSS/JS 时，**缩进多一个空格、少一个空格**，直接：

* hexo clean 无效
* hexo g 直接 FATAL 崩溃
* 整个博客无法部署

### 原因

YAML 对缩进极度严格，CSS、JS 粘贴错乱直接解析失败。

### 避坑方案

所有注入代码必须**统一对齐**，不要随意换行、不要乱改缩进。

## 五、坑点5：背景图路径写法错误导致编译报错

### 错误写法（我之前写错的）

|  |  |
| --- | --- |
| ``` 1 ``` | ``` background-image: /img/cat.jpg!important; ``` |

### 报错原因

缺少 `url()`、缺少引号，YAML 直接解析爆炸。

### 正确标准写法

|  |  |
| --- | --- |
| ``` 1 ``` | ``` background-image: url('/img/cat.jpg') !important; ``` |

## 六、坑点6：请求格式不匹配大模型规范，一直返回失败

大模型接口对 body 格式要求极严：

* 必须 `Content-Type: application/json`
* 必须 `JSON.stringify()` 序列化参数
* 参数字段名必须和模型文档完全一致

我刚开始字段写错、格式不对，一直请求成功但返回空数据。

## 七、坑点7：无加载状态、无防抖，重复点击多发请求

### 问题

网络慢的时候，用户疯狂点发送，前端连续发起几十条请求，造成：

* 重复问答
* 额度快速消耗
* 页面消息错乱

### 我的解决方案

增加 loading 占位，请求期间禁止重复发送，完美解决。

## 八、前端调用大模型终极避坑总结（干货）

1. **永远不要前端直写密钥** = 防盗刷
2. **线上绝对无法绕过 CORS** = 必须代理
3. **fetch 必须判断 res.ok** = 错误捕获
4. **Hexo 注入代码严格控制缩进** = 避免编译崩溃
5. **所有图片、资源路径必须标准 url(‘’)**
6. **必须加 loading、防抖、异常提示** = 用户体验
