# 《全文检索 VS FAISS 向量检索》

## 1、全文检索 full

### 原理

所有上传 PDF 文字**全部合并存在程序内存字符串**，提问时直接截取文档前 3500 个字塞进提示词丢给大模型。

* ✅ 优点：**不用向量接口、不用 FAISS 库、不会索引损坏、启动快零报错**
* ❌ 缺点：文档太长只能看前面内容，后面内容 AI 读取不到，容易超出模型上下文
* ✔适用：合同、协议书、十几页以内小 PDF

## 2、FAISS 向量检索 faiss

### 原理

1.PDF 自动切成小段文字

2. 调用通义千问向量接口，文字变成一串数字（向量），保存在本地`faiss_db`文件夹
3. 提问也转为向量，在向量库里**查找相似度最高 3 段原文**，只把 3 小段发给大模型

* ✅ 优点：几百页长篇书籍也能用，只调取相关片段，不浪费 token、不会超长超限、查询精准
* ❌ 缺点：依赖通义 KEY、依赖向量接口、文件异常容易损坏向量索引
* ✔适用：说明书、长篇教材、上百页大 PDF

## 项目独有设计

**上传一次 PDF，自动同时生成两套数据：内存全文 + FAISS 向量库**，前端下拉一键切换，不用重复上传文件。

## 快速选用口诀

小文件用全文，大文件用向量。

# 结论：**FAISS 向量检索模式 = 标准轻量化 RAG；全文模式不算 RAG**

## 1、FAISS 向量检索 ✅ 完整实现 RAG 架构

RAG 标准四步：**文档加载→文本分割→向量化存入向量库→问题召回片段→拼接 prompt 交给 LLM**，你的代码全走完：

1. 加载：PyPDF2 读取多份 PDF 文本
2. 分片：`RecursiveCharacterTextSplitter`拆分 chunk
3. 向量化：通义 Embedding 把文本转向量存入 FAISS 本地向量库
4. 检索：用户问题转向量，相似度搜索召回 Top3 相关文档片段
5. 生成：片段 + 问题组装提示词送入豆包 / 智谱 / 通义大模型回答

> 这就是最经典本地 RAG 知识库。

## 2、全文检索 ❌ 不属于 RAG

只是**全文截取 + 上下文拼接直传大模型**，没有向量、没有相似度检索，属于「上下文灌入问答」，是简易兜底方案。

## 3、项目亮点

一套项目**双模式融合**：

* 开启 FAISS=RAG 知识库；
* 切换全文 = 极简上下文问答；
* 一次上传 PDF 自动生成【内存全文 + 向量库】两份数据，按需一键切换，兼顾稳定性 + 长文档 RAG 能力。

## 4、一句话总结项目定位

**自研双模式轻量化 RAG 系统：小文档简易全文问答，大文档标准 RAG 向量检索。**

# 补充

# 直白说：我是**没有本地下载 RAG 大模型，是 API 在线调用，属于云端 RAG**

## 1、没下载任何本地模型

1. **LLM 大模型（豆包 / 智谱 / 通义）**：全是填 API 密钥，走厂商云端接口远程调用，电脑无模型文件；
2. **Embedding 向量模型（text-embedding-v1）**：也是通义云端接口，文字发给阿里服务器生成向量，**没把向量模型下载到本地**；
3. FAISS 只是向量数据库引擎（存数字），不是 AI 模型。

## 2、RAG 类型：API 云 RAG

标准 RAG 分两种：

* **本地 RAG**：把大模型 + 向量模型全部下载到电脑本地，离线运行（如 Qwen、Llama 本地部署）
* **云端 API-RAG（你现在这套）**：文档本地存在 FAISS，**向量、大模型全部调用第三方云端 API**，就是工业常用轻量化 RAG。

## 3、项目总结

> 项目采用**API 架构轻量化 RAG**，文档解析、分片、向量存储本地化（FAISS），文本向量化与大模型生成调用通义、智谱、豆包在线 API，无需本地部署权重文件，部署简单、开箱即用，同时附带非 RAG 全文检索兜底方案。

## 补充

想要变成**本地离线 RAG**才需要下载：本地 Embedding 模型 + 本地 LLM 模型。

**全文检索（非 RAG）**

文档放内存，截取部分全文塞给 AI，短文档好用，长文档丢内容、超限。

**FAISS 向量检索（标准 RAG）**

文档分片→云端向量化→本地 FAISS 存向量→问题相似度召回相关片段→喂给大模型，**完整 RAG 全流程**；依托 API，不用本地部署大模型 / 向量模型。

* FAISS 向量模式：RAG 检索增强生成（增强生效）

  借助外部 PDF 知识库检索内容，补强 LLM 答案，就是标准 RAG。
* 全文模式：无检索增强

  直接全文档截断灌入上下文，属于 Prompt 填充，不属于 RAG。

## 本次开发踩坑（干货）

1. 初期只用 FAISS：向量类缺少`__call__`，LangChain 调用报错`对象不可调用`，FAISS 直接 500；
2. 旧 faiss\_db 索引损坏，每次换新方案必须删除文件夹重建；
3. 密钥区分：LLM 密钥用来聊天、QWEN\_KEY 用来生成向量，缺一 FAISS 不可用；
4. 优化：做成双模式架构，一次上传 PDF 生成两份数据，一键切换，兼顾稳定性和 RAG 长文本能力。
