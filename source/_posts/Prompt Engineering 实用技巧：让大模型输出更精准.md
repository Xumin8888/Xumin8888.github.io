## 前言

你有没有过这样的经历：
- 同样一个问题，别人问 AI 得到的答案又准又好，你问出来的结果却差强人意
- 让 AI 写代码，它总是漏掉一些细节，还要反复改好几遍
- 想让 AI 生成一篇结构清晰的文章，结果它写得东一榔头西一棒子

问题可能不在于 AI，而在于你的「提问方式」——也就是 Prompt（提示词）。

Prompt Engineering（提示词工程）是 AI 时代的必备技能。同样的大模型，用好提示词和用不好，输出质量可能天差地别。

这篇文章，我会分享经过大量实践验证的 **Prompt 实用技巧**，全部都是拿来就能用的干货。不管是日常工作用 AI 提效，还是做 AI 应用开发，这些技巧都用得上。

## 一、Prompt 的核心原则

在讲具体技巧之前，先说说写好 Prompt 的几个核心原则。

### 1.1 清晰明确，不要模糊

**反面例子**：
> 帮我写个登录页

**正面例子**：
> 用 Vue 3 + Element Plus 写一个登录页，要求：
> 1. 包含账号、密码、验证码三个输入框
> 2. 有「记住密码」复选框和「忘记密码」链接
> 3. 底部有「立即注册」入口
> 4. 表单验证：账号不少于3位，密码不少于6位
> 5. 使用 Composition API + `<script setup>` 语法

越具体、越明确，AI 输出的结果就越符合你的预期。

### 1.2 给角色，给背景

大模型是「万金油」，但如果你告诉它具体的身份和背景，它的回答会更专业。

**反面例子**：
> 怎么优化前端性能？

**正面例子**：
> 你是一个有 5 年经验的前端性能优化专家。现在有一个电商网站，首屏加载需要 5 秒，用户反馈很慢。请从前端角度给出具体的优化方案，按优先级排序。

### 1.3 限定输出格式

如果你想要特定格式的输出（比如 JSON、Markdown 表格、代码等），一定要在 Prompt 里明确说出来。

**反面例子**：
> 列出常用的前端状态管理库

**正面例子**：
> 列出 5 个常用的前端状态管理库，用 Markdown 表格输出，包含以下列：
> - 库名
> - 适用框架
> - 优缺点
> - 推荐指数（1-5星）

### 1.4 给例子（Few-shot）

如果你有具体的示例，直接给 AI 看，它会学得更快。

**例子**：
> 请把以下中文技术术语翻译成英文：
> 
> 示例：
> 输入：虚拟 DOM
> 输出：Virtual DOM
> 
> 输入：服务端渲染
> 输出：Server-Side Rendering
> 
> 输入：懒加载
> 输出：

## 二、十大实用 Prompt 技巧

### 技巧一：角色设定法（Role Prompting）

给 AI 设定一个专业角色，让它站在这个角色的角度回答问题。

**模板**：
```
你是一个【角色】，拥有【N年经验/专业背景】。
你的擅长领域是【XXX】。
现在请你【具体任务】。
```

**前端常用角色**：
- 你是一个资深前端架构师，精通 Vue、React 和工程化
- 你是一个 CSS 大神，擅长各种复杂布局和动画
- 你是一个前端性能优化专家，有丰富的实战经验
- 你是一个代码审查专家，擅长发现代码中的问题和潜在 bug

**实战示例**：
> 你是一个资深前端架构师，有 8 年开发经验。现在团队要从 Vue 2 升级到 Vue 3，项目比较大，有 200+ 页面。请你制定一个详细的迁移方案，包括迁移步骤、风险点和注意事项。

### 技巧二：分步思考法（Chain of Thought）

让 AI 一步一步地思考，而不是直接给出答案。这对于复杂问题特别有效，能大幅提升准确率。

**关键词**：
- 一步一步来
- 先分析，再给出答案
- 请给出你的思考过程

**实战示例**：
> 下面这段代码有什么问题？请一步一步分析：
> 
> ```javascript
> function asyncAdd(a, b) {
>   let result;
>   setTimeout(() => {
>     result = a + b;
>   }, 1000);
>   return result;
> }
> 
> console.log(asyncAdd(1, 2));
> ```

### 技巧三：输出格式化

明确指定输出的格式和结构，让 AI 的回答更规整。

**常用格式**：
- Markdown 格式
- JSON 格式
- 表格形式
- 分点列举
- 代码块

**实战示例**：
> 请对比 React 和 Vue 的区别，用 Markdown 表格输出，包含以下维度：
> - 学习曲线
> - 生态系统
> - 性能
> - 适用场景
> - 就业市场
> 
> 最后再给一段总结，说说新手该怎么选。

### 技巧四：约束条件法

给 AI 加上各种约束，让它的输出更符合你的要求。

**常用约束**：
- 字数限制（不少于/不超过 XXX 字）
- 语言风格（正式/口语化/幽默/专业）
- 受众定位（给新手/给专家/给老板）
- 排除某些内容（不要说废话/不要解释基础概念）

**实战示例**：
> 用大白话解释什么是闭包，要求：
> 1. 不超过 200 字
> 2. 不用专业术语，用生活中的例子比喻
> 3. 面向完全不懂编程的小白

### 技巧五：Few-shot 示例法

给 AI 几个示例，让它照着例子的格式和风格输出。

**实战示例**：
> 请按照以下格式，给 3 个前端面试题：
> 
> 【题目】
> 什么是事件循环？
> 
> 【考察点】
> 对 JS 异步机制的理解
> 
> 【参考答案】
> （此处省略答案）
> 
> ---
> 
> 【题目】
> ...

### 技巧六：反向提问法

当你不确定该怎么问，或者想让 AI 帮你梳理思路时，可以让 AI 来问你问题。

**实战示例**：
> 我想做一个 AI 相关的前端项目，用来写进简历。请你帮我梳理一下，你需要了解哪些信息才能给我推荐合适的项目方向？请列出 5-10 个问题。

### 技巧七：迭代优化法

不要指望一次就能得到完美的结果。用好 AI 的正确姿势是「迭代优化」：
1. 先让 AI 给一版
2. 指出哪里不好，要求修改
3. 反复调整，直到满意

**迭代时的常用话术**：
- 上面的回答在 XXX 方面不够好，请优化一下
- 能不能再详细讲讲 XXX 部分？
- 这个方案有个问题：XXX，能不能调整一下？
- 风格太正式了，能不能更口语化一点？

**关键**：每次只改一点，逐步逼近理想结果。

### 技巧八：知识增强法（RAG 思路）

如果问题涉及特定的知识或上下文，把相关信息「喂」给 AI，它的回答会准确很多。

**模板**：
```
请根据以下内容回答问题：

【参考资料】
（把你的文档、文章、代码等贴在这里）

【问题】
（你的问题）

要求：答案必须来自参考资料，不要编造。如果参考资料中没有相关信息，请说明。
```

这其实就是 RAG 的基本思路——先检索相关资料，再基于资料生成答案。

### 技巧九：结构化思维法

对于复杂的任务，可以给 AI 一个结构化的框架，让它按照框架来输出。

**常用框架**：
- 是什么-为什么-怎么办
- 优点-缺点-适用场景
- 现状-问题-方案-风险
- 需求分析-技术选型-实现步骤-注意事项

**实战示例**：
> 请从以下几个方面，详细讲讲前端工程化：
> 1. 什么是前端工程化（定义）
> 2. 为什么需要前端工程化（解决了什么问题）
> 3. 前端工程化包含哪些内容（模块化、构建、部署等）
> 4. 常用的工程化工具有哪些
> 5. 新手怎么学习前端工程化

### 技巧十：反思验证法

让 AI 自己检查和反思输出的内容，能有效减少错误。

**常用话术**：
- 请检查上面的回答，看看有没有错误或遗漏
- 你刚才给出的方案有什么潜在问题？
- 请从反面角度，说说这个方案的缺点
- 如果让你重新回答，你会怎么优化？

**实战示例**：
> 你给出的这个技术方案听起来不错。但我担心有风险，请你站在反方的角度，说说这个方案可能存在哪些问题和隐患？

## 三、前端开发常用 Prompt 模板

这里给大家整理几个前端开发中常用的 Prompt 模板，直接套用就行。

### 模板一：代码生成

```
你是一个资深前端开发工程师，精通 Vue 3 / React 和 TypeScript。
请帮我实现一个【组件/功能描述】，要求：
1. 技术栈：Vue 3 + TypeScript + Element Plus
2. 功能点：
   - 【功能点1】
   - 【功能点2】
   - 【功能点3】
3. 代码规范：
   - 使用 Composition API + <script setup>
   - 类型定义清晰
   - 有适当的注释
   - 错误处理完善

请直接给出完整可运行的代码。
```

### 模板二：代码审查

```
你是一个严格的代码审查专家，请审查下面这段代码，从以下几个方面给出意见：
1. 代码规范和可读性
2. 潜在的 bug 和逻辑问题
3. 性能优化空间
4. 安全性问题
5. 可维护性和扩展性

代码：
```
（粘贴你的代码）
```

请分点列出问题，并给出修改建议。问题严重程度用 🔴（严重）、🟡（中等）、🟢（建议）标注。
```

### 模板三：Bug 排查

```
我遇到了一个前端 bug，请帮我分析原因并给出解决方案：

【现象描述】
（描述 bug 现象）

【预期行为】
（描述预期应该是什么样的）

【相关代码】
```
（粘贴相关代码）
```

【报错信息】
（粘贴报错信息，如果有的话）

【我已经尝试过的方法】
（列出你已经试过什么）

请一步一步分析可能的原因，并给出排查思路和解决方案。
```

### 模板四：学习辅导

```
你是一个耐心的前端技术导师，我是一个前端初学者，正在学习【某个知识点】。

请你：
1. 先用大白话给我讲清楚这个概念是什么
2. 举一个简单易懂的例子
3. 说说它解决了什么问题，为什么要用它
4. 给我 3 道练习题，从易到难
5. 最后告诉我学习这个知识点有哪些常见的坑

注意：不要用太专业的术语，尽量口语化。
```

### 模板五：技术方案设计

```
你是一个资深前端架构师，请帮我设计一个【项目/功能】的技术方案。

【需求描述】
（详细描述需求）

【技术栈】
- 框架：Vue 3 / React
- UI 库：Element Plus / Ant Design
- 其他：（根据情况补充）

请从以下几个方面给出方案：
1. 整体架构设计
2. 目录结构规划
3. 核心模块设计
4. 关键技术点和实现思路
5. 可能遇到的难点和应对方案
```

## 四、用好 AI 的正确姿势

### 4.1 AI 是助手，不是神

不要迷信 AI 的答案，它经常会「一本正经地胡说八道」。尤其是：
- 最新的技术知识（它的训练数据有截止日期）
- 具体的 API 参数（很容易记错）
- 数学计算和逻辑推理（容易出错）

**原则**：AI 给的东西，一定要自己验证一遍。

### 4.2 培养「批判性思维」

用 AI 的时候，要带着「审查」的眼光：
- 这段代码真的能跑吗？有没有遗漏？
- 这个结论对吗？有没有其他可能性？
- 它说的这个 API 是这么用的吗？要不要查下文档？

这个审查和验证的过程，本身就是一种很好的学习。

### 4.3 建立自己的 Prompt 库

把好用的 Prompt 收集起来，分类整理：
- 代码生成类
- 代码审查类
- 学习辅导类
- 文案写作类
- 项目规划类

用的时候直接拿出来改一改，效率会高很多。

### 4.4 持续迭代，持续优化

Prompt Engineering 是一门实践的艺术，没有「最好」，只有「更好」。
- 多用、多试、多总结
- 看到好的 Prompt 就收藏起来
- 不断优化自己常用的模板

## 结语

Prompt Engineering 说难也难，说简单也简单。

说它难，是因为要真正做到「精准控制 AI 输出」，需要大量的实践和积累。

说它简单，是因为核心逻辑就那么几条——**说清楚、给角色、给例子、给格式、多迭代**。

对于前端开发者来说，Prompt Engineering 是 AI 时代性价比最高的技能之一。不需要学复杂的算法，不需要懂底层原理，只要把提示词写好，就能让 AI 成为你的超级助手。

希望这篇文章里的技巧和模板，能帮你更好地使用 AI，提升工作效率。记住——**AI 会不会用，全看你会不会问**。
