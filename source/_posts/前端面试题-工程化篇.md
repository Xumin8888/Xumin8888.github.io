## 一、Webpack

### 1. Webpack 是什么？

Webpack 是一个现代 JavaScript 应用程序的**静态模块打包器**。它会递归地构建一个依赖关系图，其中包含应用程序需要的每个模块，然后将所有这些模块打包成一个或多个 bundle。

### 2. Webpack 的核心概念？

| 概念 | 说明 |
|------|------|
| Entry | 入口，Webpack 打包的起点 |
| Output | 输出，打包后的文件输出位置和命名 |
| Loader | 模块转换器，处理非 JS 文件（CSS、图片等） |
| Plugin | 插件，执行更广泛的任务（打包优化、资源管理等） |
| Mode | 模式，development / production / none |

### 3. 常见的 Loader？

- **样式处理**：style-loader、css-loader、less-loader、sass-loader、postcss-loader
- **JS 处理**：babel-loader、ts-loader
- **文件处理**：file-loader、url-loader、asset modules（Webpack5）
- **Vue/React**：vue-loader、babel-preset-react

### 4. 常见的 Plugin？

- **HtmlWebpackPlugin**：自动生成 HTML 文件，引入打包后的 JS
- **CleanWebpackPlugin**：打包前清理输出目录
- **MiniCssExtractPlugin**：提取 CSS 到单独文件
- **CssMinimizerWebpackPlugin**：压缩 CSS
- **TerserWebpackPlugin**：压缩 JS
- **DefinePlugin**：定义全局常量
- **HotModuleReplacementPlugin**：热模块替换

### 5. Webpack 构建流程？

1. **初始化参数**：从配置文件和 Shell 语句中读取与合并参数
2. **开始编译**：初始化 Compiler 对象，加载所有插件
3. **确定入口**：根据 Entry 找出所有入口文件
4. **编译模块**：从入口文件出发，调用所有配置的 Loader 对模块进行翻译
5. **完成模块编译**：得到每个模块被翻译后的内容以及它们之间的依赖关系
6. **输出资源**：根据入口和模块之间的依赖关系，组装成一个个包含多个模块的 Chunk
7. **输出完成**：将所有 Chunk 转换成文件，输出到 Output 目录

### 6. 热更新（HMR）原理？

1. **webpack-dev-server** 启动本地服务
2. Webpack 监听文件变化，重新编译模块
3. 通过 **websocket** 建立浏览器和服务器之间的通信
4. 服务器推送更新通知（hash 和模块列表）
5. 浏览器通过 HMR runtime 机制热替换更新的模块

## 二、Vite

### 1. Vite 为什么比 Webpack 快？

| 特性 | Webpack | Vite |
|------|---------|------|
| 启动方式 | 先打包再启动服务器 | 先启动服务器，按需编译 |
| 开发环境 | 打包所有模块 | 利用浏览器原生 ES Module |
| 冷启动 | 慢（需要打包全部） | 快（只启动服务器） |
| 热更新 | 重新编译相关模块 | 只更新变更的模块 |
| 构建生产 | - | 使用 Rollup 打包 |

**核心原理：**
- **开发环境**：使用浏览器原生 ESM，按需编译，不需要打包
- **生产环境**：使用 Rollup 打包，因为 Rollup 对 ESM 支持更好，产物体积更小

### 2. Vite 的特点？

- 极速的服务启动
- 轻量快速的热重载（HMR）
- 丰富的功能（TypeScript、JSX、CSS 等开箱即用）
- 优化的构建（Rollup 预配置）
- 通用的插件（Rollup 插件生态）
- 完全类型化的 API

## 三、Git

### 1. Git 和 SVN 的区别？

| 特性 | Git | SVN |
|------|-----|-----|
| 类型 | 分布式 | 集中式 |
| 仓库 | 每个开发者都有完整仓库 | 只有中央仓库 |
| 离线工作 | ✅ 可以 | ❌ 不行 |
| 速度 | 快（本地操作） | 慢（依赖网络） |
| 分支 | 轻量级，快速 | 较重 |
| 安全性 | 高（分布式备份） | 低（中央仓库挂了就没了） |

### 2. Git 工作流程？

**工作区 → 暂存区 → 本地仓库 → 远程仓库**

- `git add`：工作区 → 暂存区
- `git commit`：暂存区 → 本地仓库
- `git push`：本地仓库 → 远程仓库
- `git pull`：远程仓库 → 工作区
- `git fetch`：远程仓库 → 本地仓库

### 3. 常见 Git 命令？

```bash
# 基础操作
git init                    # 初始化仓库
git status                  # 查看状态
git add .                   # 添加到暂存区
git commit -m "msg"         # 提交
git log                     # 查看提交记录

# 分支操作
git branch                  # 查看分支
git branch dev              # 创建分支
git checkout dev            # 切换分支
git merge dev               # 合并分支
git rebase dev              # 变基
git branch -d dev           # 删除分支

# 远程操作
git remote add origin url   # 添加远程仓库
git push origin main        # 推送到远程
git pull origin main        # 拉取并合并
git clone url               # 克隆仓库

# 撤销操作
git reset --hard HEAD^      # 回退到上一个版本
git checkout -- file        # 撤销工作区修改
git revert commitId         # 撤销指定提交（生成新提交）
```

### 4. merge 和 rebase 的区别？

**merge：**
- 保留完整的提交历史
- 会生成一个合并提交
- 分支历史分叉，能看到合并操作

**rebase：**
- 提交历史是线性的，更简洁
- 将当前分支的提交"移动"到目标分支后面
- 改写提交历史
- 不要在公共分支上使用 rebase

### 5. git pull 和 git fetch 的区别？

- **git fetch**：只拉取远程仓库的更新，不会自动合并
- **git pull**：拉取并自动合并（相当于 git fetch + git merge）

## 四、模块化

### 1. 常见的模块化方案？

| 方案 | 特点 | 环境 |
|------|------|------|
| CommonJS | `require` / `module.exports`，同步加载 | Node.js |
| AMD | `define` / `require`，异步加载 | 浏览器（RequireJS） |
| CMD | 类似 AMD，按需加载 | 浏览器（SeaJS） |
| ES Module | `import` / `export`，静态分析 | 浏览器 + Node.js |
| UMD | 兼容 CommonJS、AMD、全局变量 | 通用 |

### 2. CommonJS 和 ES Module 的区别？

| 特性 | CommonJS | ES Module |
|------|----------|-----------|
| 加载方式 | 运行时加载，同步 | 编译时加载，静态分析 |
| 导出 | 值的拷贝 | 值的引用（动态绑定） |
| 顶层 this | 指向模块本身 | undefined |
| 循环加载 | 返回已执行部分的值 | 支持，靠动态绑定 |
| 使用环境 | Node.js | 浏览器 + Node.js |
| 树形摇树 | 不支持 | 支持 |

## 五、前端性能优化

### 1. 从输入 URL 到页面加载完成的优化？

**网络层：**
- DNS 预解析
- 使用 CDN
- 减少 HTTP 请求
- 使用 HTTP/2
- 开启 Gzip / Brotli 压缩

**缓存策略：**
- 强缓存（Cache-Control）
- 协商缓存（ETag / Last-Modified）
- Service Worker 离线缓存

**资源加载：**
- 路由懒加载
- 图片懒加载
- 预加载（preload / prefetch）
- 代码分割

**渲染优化：**
- 减少重排重绘
- 使用 transform / opacity 做动画
- 防抖节流
- 虚拟列表

**构建优化：**
- Tree Shaking
- 压缩代码
- 按需引入
- 依赖外部化（externals）
