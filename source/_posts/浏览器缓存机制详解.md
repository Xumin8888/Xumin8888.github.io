## 前言

浏览器缓存是前端性能优化的重要手段。正确理解和使用缓存，可以大幅提升页面加载速度，减少服务器压力。本文将全面讲解浏览器缓存机制。

## 一、缓存的分类

### 1.1 按存储位置分

1. **内存缓存（Memory Cache）**：读取快，容量小，关闭页面就失效
2. **磁盘缓存（Disk Cache）**：读取稍慢，容量大，持久化存储
3. **Service Worker Cache**：开发者可控，灵活度最高

### 1.2 按缓存策略分

1. **强缓存**：不发送请求，直接使用缓存
2. **协商缓存**：发送请求验证资源是否更新

## 二、强缓存

### 2.1 Expires（HTTP/1.0）

```http
Expires: Wed, 21 Oct 2026 07:28:00 GMT
```

- 指定一个绝对时间，在这时间之前都使用缓存
- 缺点：服务器和客户端时间可能不一致

### 2.2 Cache-Control（HTTP/1.1）

```http
Cache-Control: max-age=3600
```

**常用指令：**

| 指令 | 说明 |
| --- | --- |
| `max-age=3600` | 缓存有效期 3600 秒 |
| `public` | 可以被任何对象缓存 |
| `private` | 只能被终端用户缓存 |
| `no-cache` | 需要协商缓存验证 |
| `no-store` | 不缓存任何内容 |
| `s-maxage` | 代理服务器缓存时间 |

**示例：**

```http
Cache-Control: public, max-age=3600, s-maxage=86400
```

### 2.3 强缓存的状态码

- **200 (from memory cache)**：来自内存缓存
- **200 (from disk cache)**：来自磁盘缓存

## 三、协商缓存

当强缓存过期后，进入协商缓存流程。浏览器发送请求到服务器，服务器判断资源是否有更新。

### 3.1 Last-Modified / If-Modified-Since

```http
# 响应头
Last-Modified: Wed, 21 Oct 2025 07:28:00 GMT

# 请求头
If-Modified-Since: Wed, 21 Oct 2025 07:28:00 GMT
```

- 服务器返回资源的最后修改时间
- 浏览器下次请求时带上这个时间
- 服务器对比时间，没变则返回 304，有变化返回 200 + 新资源

**缺点：**
- 只能精确到秒
- 文件修改后又改回原样，时间会变但内容没变

### 3.2 ETag / If-None-Match

```http
# 响应头
ETag: "abc123def456"

# 请求头
If-None-Match: "abc123def456"
```

- 服务器根据文件内容生成唯一标识（类似指纹）
- 浏览器下次请求时带上 ETag
- 服务器对比标识，没变则返回 304，有变化返回 200 + 新资源

**优点：**
- 精确到内容变化
- 不受修改时间影响

### 3.3 协商缓存的状态码

- **304 Not Modified**：资源未修改，使用缓存
- **200 OK**：资源已修改，返回新资源

### 3.4 两者对比

| 特性 | Last-Modified | ETag |
| --- | --- | --- |
| 精度 | 秒级 | 内容级 |
| 性能 | 高 | 低（需要计算） |
| 优先级 | 低 | 高 |

> 当 ETag 和 Last-Modified 同时存在时，ETag 优先级更高。

## 四、缓存流程图

```
浏览器发起请求
     │
     ├─ 有缓存吗？
     │    ├─ 没有 → 发请求 → 服务器返回 200 + 资源 → 存入缓存
     │    └─ 有 → 检查强缓存是否过期
     │              ├─ 没过期 → 直接使用缓存（200 from cache）
     │              └─ 已过期 → 发协商请求
     │                        ├─ 304 → 使用缓存
     │                        └─ 200 → 更新缓存
```

## 五、缓存策略实践

### 5.1 HTML 文件

```http
Cache-Control: no-cache
```

- HTML 使用协商缓存，确保用户能看到最新内容

### 5.2 静态资源（JS/CSS/图片）

```http
Cache-Control: max-age=31536000
```

- 资源文件名带上 hash，缓存时间设为一年
- 文件内容变化时，hash 变化，URL 变化，自动获取新文件

### 5.3 频繁变化的数据

```http
Cache-Control: no-cache
```

- 使用协商缓存，每次验证

### 5.4 不缓存的内容

```http
Cache-Control: no-store
```

- 敏感信息不缓存

## 六、Service Worker 缓存

### 6.1 什么是 Service Worker

- 运行在浏览器后台的独立线程
- 可以拦截和处理网络请求
- 离线访问的基础

### 6.2 注册 Service Worker

```javascript
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/sw.js')
      .then(registration => {
        console.log('注册成功:', registration.scope)
      })
      .catch(error => {
        console.log('注册失败:', error)
      })
  })
}
```

### 6.3 缓存静态资源

```javascript
// sw.js
const CACHE_NAME = 'my-cache-v1'
const urlsToCache = [
  '/',
  '/index.html',
  '/styles.css',
  '/app.js',
  '/images/logo.png'
]

// 安装阶段：缓存资源
self.addEventListener('install', event => {
  event.waitUntil(
    caches.open(CACHE_NAME)
      .then(cache => cache.addAll(urlsToCache))
  )
})

// 拦截请求
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request)
      .then(response => {
        // 缓存命中，返回缓存
        if (response) {
          return response
        }
        // 没有缓存，发起请求
        return fetch(event.request)
      })
  )
})

// 激活阶段：清理旧缓存
self.addEventListener('activate', event => {
  event.waitUntil(
    caches.keys().then(cacheNames => {
      return Promise.all(
        cacheNames
          .filter(name => name !== CACHE_NAME)
          .map(name => caches.delete(name))
      )
    })
  )
})
```

### 6.4 缓存策略

**1. 缓存优先（Cache First）**

```javascript
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request).then(cached => {
      return cached || fetch(event.request).then(response => {
        const responseClone = response.clone()
        caches.open(CACHE_NAME).then(cache => {
          cache.put(event.request, responseClone)
        })
        return response
      })
    })
  )
})
```

**2. 网络优先（Network First）**

```javascript
self.addEventListener('fetch', event => {
  event.respondWith(
    fetch(event.request)
      .then(response => {
        const responseClone = response.clone()
        caches.open(CACHE_NAME).then(cache => {
          cache.put(event.request, responseClone)
        })
        return response
      })
      .catch(() => caches.match(event.request))
  )
})
```

**3. Stale-While-Revalidate**

```javascript
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request).then(cached => {
      const fetchPromise = fetch(event.request).then(response => {
        caches.open(CACHE_NAME).then(cache => {
          cache.put(event.request, response.clone())
        })
        return response
      })
      return cached || fetchPromise
    })
  )
})
```

## 七、缓存相关的 HTTP 头总结

| 头字段 | 类型 | 说明 |
| --- | --- | --- |
| `Expires` | 强缓存 | 过期时间（HTTP/1.0） |
| `Cache-Control` | 强缓存 | 缓存控制指令（HTTP/1.1） |
| `Last-Modified` | 协商缓存 | 最后修改时间 |
| `If-Modified-Since` | 协商缓存 | 请求时带上的修改时间 |
| `ETag` | 协商缓存 | 资源唯一标识 |
| `If-None-Match` | 协商缓存 | 请求时带上的 ETag |

## 八、常见问题

### 8.1 怎么禁用缓存？

```http
Cache-Control: no-cache, no-store, must-revalidate
```

### 8.2 刷新按钮和强制刷新的区别

- **普通刷新（F5）**：跳过强缓存，走协商缓存
- **强制刷新（Ctrl+F5）**：跳过所有缓存，直接请求服务器

### 8.3 缓存失效了怎么更新？

1. **文件名加 hash**：内容变了，文件名变了，自然获取新的
2. **查询参数加版本号**：`app.js?v=2.0`
3. **修改 ETag/Last-Modified**：服务器端控制

## 九、总结

浏览器缓存是性能优化的重要手段：

1. **强缓存**：`Cache-Control` + `Expires`，不发请求
2. **协商缓存**：`ETag` + `Last-Modified`，发请求验证
3. **Service Worker**：开发者完全可控，实现离线访问
4. **合理策略**：不同资源用不同的缓存策略

掌握缓存机制，合理配置缓存策略，可以让你的网站快如闪电！
