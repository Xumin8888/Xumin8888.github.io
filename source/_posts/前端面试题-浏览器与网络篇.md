## 一、浏览器原理

### 1. 输入 URL 到页面显示的全过程？

1. **URL 解析**：浏览器解析 URL，确定协议、域名、端口、路径
2. **DNS 解析**：将域名解析为 IP 地址（DNS 缓存 → 本地 hosts → 递归查询）
3. **TCP 连接**：三次握手建立连接
4. **发送 HTTP 请求**：构建请求报文，发送给服务器
5. **服务器处理**：服务器处理请求，返回响应报文
6. **浏览器接收响应**：解析响应头和响应体
7. **渲染页面**：
   - 解析 HTML 构建 DOM 树
   - 解析 CSS 构建 CSSOM 树
   - 合并为渲染树（Render Tree）
   - 布局（Layout）：计算元素位置和大小
   - 绘制（Paint）：将像素绘制到屏幕
   - 合成（Composite）：将多个层合并显示
8. **TCP 断开**：四次挥手断开连接

### 2. 什么是重排（回流）和重绘？

**重排（Reflow / Layout）：**
- 元素的几何属性（位置、大小）发生变化
- 需要重新计算布局
- 代价高，影响性能

**重绘（Repaint / Paint）：**
- 元素的外观属性（颜色、背景）发生变化
- 不需要重新计算布局
- 比重排代价低

**触发重排的操作：**
- 添加/删除 DOM 元素
- 改变元素位置、大小、内容
- 改变浏览器窗口大小
- 获取某些属性（offsetWidth、clientWidth 等）

**优化方法：**
- 使用 transform 做动画（不触发重排，直接走合成层）
- 使用 class 批量修改样式
- 离线操作 DOM（DocumentFragment）
- 用 will-change 或 translateZ 提升为合成层

## 二、HTTP 协议

### 1. HTTP 常见状态码？

| 状态码 | 含义 | 说明 |
|--------|------|------|
| 200 | OK | 请求成功 |
| 201 | Created | 创建成功 |
| 204 | No Content | 成功但无返回体 |
| 301 | Moved Permanently | 永久重定向 |
| 302 | Found | 临时重定向 |
| 304 | Not Modified | 协商缓存命中 |
| 400 | Bad Request | 请求参数错误 |
| 401 | Unauthorized | 未授权 |
| 403 | Forbidden | 禁止访问 |
| 404 | Not Found | 资源不存在 |
| 405 | Method Not Allowed | 方法不允许 |
| 500 | Internal Server Error | 服务器内部错误 |
| 502 | Bad Gateway | 网关错误 |
| 503 | Service Unavailable | 服务不可用 |
| 504 | Gateway Timeout | 网关超时 |

### 2. GET 和 POST 的区别？

| 特性 | GET | POST |
|------|-----|------|
| 作用 | 获取资源 | 提交数据 |
| 参数位置 | URL 中 | 请求体中 |
| 安全性 | 较低（参数暴露） | 较高 |
| 可缓存 | 可以 | 一般不可以 |
| 可收藏为书签 | 可以 | 不可以 |
| 长度限制 | 有（URL 长度限制） | 无 |
| 幂等性 | 幂等 | 不幂等 |
| 后退/刷新 | 无害 | 会重新提交 |

### 3. HTTP 和 HTTPS 的区别？

| 特性 | HTTP | HTTPS |
|------|------|-------|
| 端口 | 80 | 443 |
| 安全性 | 明文传输，不安全 | SSL/TLS 加密，安全 |
| 证书 | 不需要 | 需要 CA 证书 |
| 性能 | 快 | 稍慢（加密解密开销） |
| 协议 | HTTP | HTTP + SSL/TLS |

**HTTPS 握手过程：**
1. 客户端发送 Client Hello（支持的加密套件、随机数）
2. 服务器返回 Server Hello（选择的加密套件、随机数、证书）
3. 客户端验证证书，生成预主密钥，用服务器公钥加密发送
4. 服务器用私钥解密得到预主密钥
5. 双方根据三个随机数生成会话密钥
6. 后续使用对称加密通信

## 三、缓存

### 1. 强缓存和协商缓存？

**强缓存：** 不向服务器发请求，直接用本地缓存
- `Cache-Control: max-age=31536000`（HTTP/1.1）
- `Expires`（HTTP/1.0，绝对时间）
- 状态码：200 (from memory/disk cache)

**协商缓存：** 向服务器确认缓存是否有效
- `Last-Modified / If-Modified-Since`（基于时间）
- `ETag / If-None-Match`（基于内容哈希，更精确）
- 命中：304 Not Modified
- 未命中：200 + 新内容

### 2. 缓存位置？

- **Service Worker**：自定义缓存策略，离线可用
- **Memory Cache**：内存缓存，快，容量小，关闭标签页失效
- **Disk Cache**：磁盘缓存，稍慢，容量大，持久化
- **Push Cache**：HTTP/2 推送缓存，会话级

## 四、跨域

### 1. 什么是同源策略？

同源指：**协议 + 域名 + 端口** 都相同。

同源策略限制：
- 无法读取不同源的 Cookie、LocalStorage、IndexedDB
- 无法获取不同源的 DOM
- 不能发送 AJAX 请求到不同源（其实可以发，但响应被拦截）

### 2. 跨域解决方案？

1. **CORS（跨域资源共享）**
   - 服务端设置 `Access-Control-Allow-Origin`
   - 简单请求直接发，复杂请求先发预检请求（OPTIONS）

2. **JSONP**
   - 利用 `<script>` 标签不受同源限制
   - 只能发 GET 请求

3. **代理服务器**
   - 开发环境：webpack devServer / vite proxy
   - 生产环境：Nginx 反向代理

4. **postMessage**
   - 页面与 iframe 之间通信

5. **WebSocket**
   - 不受同源策略限制

6. **document.domain**
   - 主域相同，子域不同的场景
