## 前言

很多时候，我们在学习和开发过程中会做一些有趣的前端小项目，比如数据可视化大屏、小游戏、工具类网页应用等。如果能把这些项目直接嵌入到自己的 Hexo 博客中，既能丰富博客内容，又能作为作品集展示，可谓一举两得。

本文将详细介绍如何将无后端依赖的前端项目部署到 Hexo 博客中，涵盖 Vue、React、原生 JS 等多种技术栈的项目，以及各种注意事项和常见问题的解决方案。

## 一、核心原理与前提条件

### 1.1 实现原理

Hexo 是一个静态网站生成器，最终生成的都是纯静态文件（HTML、CSS、JS）。因此，我们只需要把前端项目打包后的静态文件放到 Hexo 的 `source` 目录下，Hexo 在生成博客时就会把这些文件一并复制到最终的 `public` 目录中，从而实现项目的嵌入。

### 1.2 前提条件

在开始之前，请确保你满足以下条件：

1. **Hexo 博客已正常搭建并可部署**：如果你还没有搭建博客，请先参考「Hexo 博客从零搭建完全指南」
2. **前端项目本地能正常运行**：项目在本地开发环境下没有报错
3. **项目无后端依赖**：项目是纯前端的，不依赖后端 API 或数据库（如果有接口调用，需要确保接口是公开可访问的）
4. **项目可以打包成静态文件**：所有现代前端框架（Vue、React、Angular 等）都支持打包

## 二、单项目部署详细步骤

下面以一个完整的流程为例，详细介绍如何将一个前端项目部署到 Hexo 博客中。

### 2.1 第一步：项目本地验证与路径配置

在打包之前，先确保项目能正常运行，并正确配置路径。

#### 本地运行验证

在项目根目录执行：

```bash
# Vue 或 Vite 项目
npm run dev

# React 项目
npm start
```

打开浏览器访问，确认页面正常显示，没有控制台报错。

#### 路径配置（非常重要！）

这是最容易出问题的一步。因为项目最终是部署在博客的子目录下的（如 `/demos/project-name/`），所以必须正确配置项目的基础路径，否则会出现资源加载失败、页面空白等问题。

##### Vite 项目（Vue 3 / React 等）

修改 `vite.config.js` 或 `vite.config.ts`：

```javascript
import { defineConfig } from 'vite'

export default defineConfig({
  // 这里的路径要和你在博客中放置的目录一致
  base: '/demos/你的项目文件夹名/',
  build: {
    outDir: 'dist',
    // 可选：打包时清空输出目录
    emptyOutDir: true
  }
})
```

> **注意**：`base` 路径必须以 `/` 开头和结尾，并且要和你实际放置的目录名完全一致。

##### Vue CLI 项目（Vue 2）

修改 `vue.config.js`：

```javascript
module.exports = {
  publicPath: '/demos/你的项目文件夹名/'
}
```

如果没有 `vue.config.js` 文件，在项目根目录新建一个。

##### React 项目（Create React App）

修改 `package.json`，添加 `homepage` 字段：

```json
{
  "name": "my-react-app",
  "version": "1.0.0",
  "homepage": "/demos/你的项目文件夹名/",
  "scripts": {
    "start": "react-scripts start",
    "build": "react-scripts build"
  }
}
```

##### 原生 HTML/CSS/JS 项目

对于原生项目，确保所有资源引用都使用相对路径：

```html
<!-- 正确：使用相对路径 -->
<link rel="stylesheet" href="./css/style.css">
<script src="./js/main.js"></script>
<img src="./images/logo.png">

<!-- 错误：使用绝对路径 -->
<link rel="stylesheet" href="/css/style.css">
<script src="/js/main.js"></script>
```

### 2.2 第二步：项目打包

路径配置完成后，执行打包命令：

```bash
# Vue / Vite 项目
npm run build

# React 项目
npm run build

# 原生项目
# 无需打包，直接使用源文件
```

打包完成后，检查项目根目录下是否生成了 `dist` 文件夹（原生项目除外），并且里面有 `index.html` 文件。

**打包检查清单：**
- [ ] `dist` 目录存在
- [ ] `dist` 目录下有 `index.html`
- [ ] `dist` 目录下有 `assets` 或类似的资源文件夹
- [ ] 没有报错信息

### 2.3 第三步：在博客中创建项目目录

进入你的 Hexo 博客目录，在 `source` 目录下创建 `demos` 文件夹（如果还没有的话），然后在 `demos` 文件夹中为你的项目创建一个子文件夹。

目录结构示意：

```
blog/
└── source/
    ├── _posts/
    └── demos/              # 所有项目的父目录
        ├── project-1/      # 第一个项目
        │   └── index.html
        ├── project-2/      # 第二个项目
        │   └── index.html
        └── your-project/   # 你的项目
            └── index.html
```

> **命名建议**：文件夹名使用英文小写，单词之间用连字符（`-`）分隔，不要使用中文、空格或特殊字符。

### 2.4 第四步：复制项目文件

将打包后的文件复制到刚创建的目录中：

1. 打开项目的 `dist` 文件夹（原生项目直接打开项目根目录）
2. 全选所有文件和文件夹（`Ctrl + A`）
3. 复制（`Ctrl + C`）
4. 进入博客的 `source/demos/你的项目文件夹/` 目录
5. 粘贴（`Ctrl + V`）

> **重要提醒**：是复制 `dist` 文件夹**里面**的所有内容，不是复制 `dist` 文件夹本身！

正确的目录结构：
```
demos/your-project/
├── index.html
├── assets/
├── css/
└── js/
```

错误的目录结构：
```
demos/your-project/
└── dist/           ❌ 多了一层 dist 目录
    ├── index.html
    └── assets/
```

### 2.5 第五步：配置 Hexo 不渲染项目文件

默认情况下，Hexo 会尝试渲染 `source` 目录下的所有 HTML 文件，这可能会导致你的项目文件被修改。为了避免这个问题，需要在 Hexo 的配置文件中设置跳过渲染。

打开 Hexo 根目录的 `_config.yml`，找到 `skip_render` 配置项（如果没有就添加），修改为：

```yaml
skip_render:
  - demos/**
```

这样配置后，`demos` 目录下的所有文件都会被直接复制，不会被 Hexo 处理。

> **注意**：`skip_render` 的路径是相对于 `source` 目录的。

### 2.6 第六步：本地预览验证

在部署到线上之前，先在本地预览一下效果：

```bash
hexo clean && hexo g && hexo s
```

然后在浏览器中访问：

```
http://localhost:4000/demos/你的项目文件夹名/
```

确认页面正常显示，所有功能都能正常使用。

### 2.7 第七步：部署到线上

本地验证无误后，执行部署命令：

```bash
hexo clean && hexo g && hexo d
```

部署完成后，访问线上地址验证：

```
https://你的博客地址/demos/你的项目文件夹名/
```

## 三、多项目管理与高效工作流

### 3.1 多项目目录结构建议

当项目数量增多时，良好的目录结构能帮你更好地管理：

```
source/demos/
├── css-animation/        # CSS 动画类项目
├── js-games/             # JS 小游戏
├── data-visualization/   # 数据可视化
├── tools/                # 工具类应用
└── vue-projects/         # Vue 项目
```

你可以按技术栈、项目类型等方式分类存放。

### 3.2 批量部署脚本

如果你有很多项目需要更新，可以写一个简单的批处理脚本来自动化复制过程。

在 Windows 下，创建一个 `deploy-demos.bat` 文件：

```batch
@echo off
echo 开始部署项目...

:: 项目1
xcopy /E /Y "D:\projects\project-1\dist\*" "D:\blog\source\demos\project-1\"

:: 项目2
xcopy /E /Y "D:\projects\project-2\dist\*" "D:\blog\source\demos\project-2\"

echo 项目部署完成！
pause
```

需要更新时，双击运行即可。

### 3.3 项目清单页面

你可以创建一个项目展示页面，把所有嵌入的项目都列出来，方便访客浏览。

创建页面：

```bash
hexo new page projects
```

然后编辑 `source/projects/index.md`，添加项目列表：

```markdown
---
title: 项目作品集
date: 2026-01-01 00:00:00
top_img: /img/bj.jpg
---

## 前端项目作品集

这里收集了我做过的一些前端小项目，点击即可在线预览。

### 数据可视化

- [数据大屏展示](/demos/data-dashboard/) - 基于 ECharts 的数据可视化大屏
- [图表库示例](/demos/chart-demo/) - 各种图表类型展示

### 小游戏

- [贪吃蛇](/demos/snake-game/) - 经典贪吃蛇游戏
- [2048](/demos/2048/) - 2048 数字消除游戏

### 工具类

- [颜色选择器](/demos/color-picker/) - 在线颜色选择工具
- [Markdown 编辑器](/demos/md-editor/) - 简易 Markdown 编辑器
```

然后在导航栏中添加这个页面的入口。

## 四、不同技术栈项目的特殊处理

### 4.1 Vue 3 + Vite 项目

除了基础的路径配置外，Vue Router 的历史模式需要额外注意：

```javascript
// router/index.js
import { createRouter, createWebHashHistory } from 'vue-router'

const router = createRouter({
  // 建议使用 hash 模式，避免刷新页面 404
  history: createWebHashHistory(),
  routes: [
    // 路由配置
  ]
})
```

> **为什么推荐 hash 模式？** 因为 GitHub Pages 不支持 history 模式的 fallback，刷新子页面会 404。如果一定要用 history 模式，需要配置 404 页面重定向。

### 4.2 React 项目

React Router 同理，推荐使用 HashRouter：

```jsx
import { HashRouter as Router, Routes, Route } from 'react-router-dom'

function App() {
  return (
    <Router>
      <Routes>
        <Route path="/" element={<Home />} />
      </Routes>
    </Router>
  )
}
```

### 4.3 多页面项目

如果你的项目有多个 HTML 页面，确保每个页面的资源路径都正确。可以在打包配置中设置相对路径：

```javascript
// vite.config.js
export default defineConfig({
  base: './',  // 使用相对路径
  build: {
    rollupOptions: {
      input: {
        main: resolve(__dirname, 'index.html'),
        about: resolve(__dirname, 'about.html')
      }
    }
  }
})
```

## 五、常见问题与解决方案

### 5.1 页面空白，控制台报 404 错误

**现象**：打开页面一片空白，F12 控制台显示 CSS/JS 文件 404。

**原因**：路径配置错误，`base` 或 `publicPath` 设置不正确。

**解决方法：**
1. 检查 `vite.config.js` 或 `vue.config.js` 中的路径配置
2. 确保路径和实际目录名完全一致（注意大小写）
3. 重新打包并复制文件

### 5.2 图片资源加载失败

**现象**：页面能显示，但图片加载不出来。

**原因**：图片路径有问题，或者图片没有被正确复制。

**解决方法：**
1. 检查图片引用路径，确保使用相对路径
2. 确认图片文件确实在对应的目录中
3. 如果是 CSS 中的背景图片，注意路径是相对于 CSS 文件的

### 5.3 Hexo 部署后项目页面样式错乱

**现象**：本地预览正常，部署后样式乱了。

**原因**：可能是 Hexo 渲染了你的 HTML 文件，修改了内容。

**解决方法：**
1. 确认 `_config.yml` 中配置了 `skip_render: demos/**`
2. 执行 `hexo clean` 后重新生成部署
3. 检查 GitHub 仓库中文件是否正确

### 5.4 刷新子页面 404

**现象**：进入项目后跳转到子路由正常，但一刷新就 404。

**原因**：GitHub Pages 不支持单页应用的 history 模式。

**解决方法：**
1. 改用 hash 路由模式（推荐）
2. 在项目目录下创建 `404.html`，内容和 `index.html` 一样（部分场景有效）

### 5.5 项目在博客 iframe 中嵌入显示问题

如果你是通过 iframe 方式嵌入项目文章中，可能遇到跨域或高度自适应问题。

**解决高度自适应：**

```html
<iframe 
  src="/demos/your-project/" 
  width="100%" 
  height="600px"
  frameborder="0"
  scrolling="auto">
</iframe>
```

或者使用第三方插件实现 iframe 高度自适应。

## 六、最佳实践与注意事项

### 6.1 项目命名规范

- 文件夹名全部使用**英文小写**
- 多个单词之间用**连字符**（`-`）分隔
- 不要使用中文、空格、特殊字符
- 名称要能体现项目内容，便于后续维护

### 6.2 文件大小优化

嵌入的项目会增加博客整体加载体积，建议：

1. **打包时开启压缩**：现代前端工具默认都会压缩
2. **图片优化**：项目中的图片尽量压缩，可以使用 TinyPNG 等工具
3. **移除调试代码**：确保打包的是生产版本
4. **按需加载**：大项目考虑使用路由懒加载

### 6.3 版本管理建议

- 项目源码建议单独用 Git 仓库管理
- 博客仓库只放打包后的文件
- 可以写一个简单的部署脚本，自动打包并复制到博客目录

### 6.4 安全注意事项

- 不要在项目中硬编码敏感信息（如 API 密钥）
- 如果项目调用第三方 API，确保接口支持跨域
- 定期检查项目依赖，及时更新有安全漏洞的包

## 七、总结

将前端项目嵌入 Hexo 博客是一个非常实用的技能，它能让你的博客内容更加丰富，也能更好地展示你的技术能力。

回顾一下核心步骤：
1. 正确配置项目的基础路径
2. 打包项目生成静态文件
3. 在博客 `source/demos/` 下创建项目目录
4. 复制打包后的文件到对应目录
5. 配置 Hexo 跳过渲染 demos 目录
6. 本地预览验证后部署上线

路径配置是最关键也是最容易出错的一步，只要路径配置正确，基本上不会有大问题。如果遇到问题，先打开浏览器控制台看看报错信息，通常能快速定位原因。

希望本文能帮助你顺利地把自己的前端项目部署到博客上，打造一个更有特色的个人技术博客！
